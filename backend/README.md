# Бэкенд информационного сайта Госархива ВКО

API `/api/v1`, поиск по каталогу, ИИ-помощник и панель сотрудника для статического фронтенда из `../frontend`.
Сайт информационный: здесь нет заявлений, заказов, оплат и официальных обращений (см. `../AGENTS.md`). Принимаются только отзывы, предложения и пожелания.

**Статус:** рабочий прототип для хакатона. Модель данных и роли — предложение, заказчиком не утверждены.

## Быстрый старт

Нужен Node.js 22+.

```bash
cd backend
npm ci
npm start                    # http://127.0.0.1:4173 — сайт и API с одного адреса
```

Без ключа модели помощник работает обычным поиском. С ИИ:

```bash
OPENAI_API_KEY=... npm start
```

Проверки:

```bash
npm run check                # tsc --noEmit + node:test (тесты не обращаются к модели)
```

Остальные настройки — в [`.env.example`](.env.example).

## Как устроено

```
frontend/ (статические модули) ──fetch──▶ /api/v1 (Hono)
                                           ├─ search/      каталог, карточка, связанные материалы
                                           ├─ ai/          планировщик запроса → поиск → ответ с источниками
                                           ├─ admin/       модерация, черновики, импорт/экспорт, аналитика, журнал
                                           ├─ auth/        роли и права, scrypt, подписанная сессия + CSRF
                                           ├─ privacy/     маскирование ИИН, телефонов, почты
                                           └─ db/          PostgreSQL (DATABASE_URL) или PGlite из снимка
```

- **Поиск** (`src/search/catalog.ts`): точный шифр («Ф. Р-136, оп. 1», «р136») ранжируется первым; затем полнотекстовый поиск (русская морфология + упрощённая казахская), смысловой (pgvector, `text-embedding-3-small`, 256 измерений) и триграммы для опечаток. Исторические названия мест расширяют запрос: Лениногорск → Риддер, Зыряновск → Алтай, ул. Мира → Головкова и т. д. (`src/domain/places.ts`).
- **Помощник** (`src/ai/assistant.ts`): вопрос маскируется → модель определяет намерение и фильтры (или эвристика без модели) → сервер ищет только опубликованные материалы → модель отвечает по пронумерованным источникам → сервер проверяет ссылки на источники и язык ответа. Модель не видит закрытых документов и личных данных посетителя. Справки об услугах — только информация и ссылки на eGov/ЦОН.
- **Права** проверяются сервером на каждом запросе (`src/auth/roles.ts`); администратор филиала видит и меняет только материалы своего филиала. Все действия пишутся в `audit_log`.
- **Статусы публикации** (`src/admin/moderation.ts`): черновик → на проверке → требует доработки / одобрено → опубликовано → архив. При публикации материал сразу индексируется для поиска и помощника; при снятии — удаляется из индекса.
- **ИИ-распознавание скана** заполняет черновик карточки (название, даты, тип, места, лица, ключевые слова) и ищет возможные дубли. Опубликовать без проверки сотрудником нельзя.
- **Аналитика** строится по обезличенным событиям; запрос показывается, только если его задавали минимум в двух разных сессиях.

## Данные

`npm run build:seed` собирает `data/seed.json` из материалов репозитория (`datasets/`, `docs/data/`, оригиналы заказчика): фонды из перечня 2018 года с историей названий, газеты, фотографии старого сайта, страницы и новости, памятные даты, филиалы (лист «Книга»; скрытый технический лист XLS не читается). Описи, дела и документы извлечены из ссылок «Основание» в публикациях. Записи `demo-*` — демонстрационные, помечены на сайте.

`npm run build:db` строит базу, считает эмбеддинги (кэш `data/embeddings.cache.json.gz`, повторный запуск не тратит API) и сохраняет снимок `data/snapshot/*.copy.gz`, из которого PGlite стартует примерно за 4 секунды.

Координаты филиалов получены геокодированием адресов (OpenStreetMap Nominatim), точность указана на странице (здание / улица / населённый пункт) и требует подтверждения архивом.

## Развёртывание

- **Vercel:** `npm run build:vercel` собирает `../.vercel/output` (Build Output API: статика + функция API). Корневой `vercel.json` запускает эту сборку при деплое. Обязательная переменная — `SESSION_SECRET`. Без `OPENAI_API_KEY` модель вызывается через Vercel AI Gateway (`AI_GATEWAY_API_KEY` или OIDC-токен проекта). Сейчас стенд на бесплатных кредитах Gateway: в них нет GPT-6 Luna и эмбеддингов, поэтому заданы `LLM_MODEL=gpt-5-nano`, `LLM_REASONING_EFFORT=minimal` (nano не поддерживает `none`) и `QUERY_EMBEDDINGS=off` (поиск по запросу без смыслового слоя). После пополнения кредитов удалить эти переменные и передеплоить — вернутся GPT-6 Luna и смысловой поиск.
- **Свой сервер:** `NODE_ENV=production SESSION_SECRET=... DATABASE_URL=postgres://... HOST=0.0.0.0 npm start` за обратным прокси с HTTPS.

## Ограничения и техдолг

- На демо-стенде база в памяти: изменения из панели живут до перезапуска экземпляра функции и не видны другим экземплярам (ADR-006). Для эксплуатации нужен `DATABASE_URL`.
- Лимит попыток входа и частоты запросов к помощнику хранится в памяти экземпляра; в эксплуатации нужен общий счётчик.
- Казахская морфология — упрощённое отсечение окончаний, качество поиска на казахском нужно измерить на реальных запросах.
- Отозвать конкретную сессию сотрудника нельзя без смены `SESSION_SECRET` (ADR-008).
- Сведения о фондах — перечень 2018 года; описи и дела представлены выборочно.

Решения: [`docs/decisions/README.md`](../docs/decisions/README.md), ADR-006…008.
