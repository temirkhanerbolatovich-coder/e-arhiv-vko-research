## Предлагаемое разделение

| Направление | Разработчик A | Разработчик B |
|---|---|---|
| Контракты | API/схема/валидация | Сценарии интерфейса/формат ответа |
| Основная работа | БД, импорт, файлы, права, поиск, ИИ | Публичные разделы, чат, каталог, просмотрщик, административные сценарии |
| Совместно | Ревью миграций, тесты доступа, контроль источников | Проверка требований, трёх языков, доступности и демонстрации |

Назначение условное; реальные имена/распределение команда выбирает сама. До параллельной разработки согласовать поля карточки, структуру ответов чата/цитат, ошибки, пагинацию и статусы. Моковые записи явно маркировать; не выдавать их за реальные архивные факты.

## Порядок работы с Git

Одна задача — одна короткая ветка и связный PR. Не изменять исходную выгрузку ради удобства импорта: правила писать отдельно. Изменение модели начинается с build_model.py и сопровождается обновлением документации/генерацией схем. Ревью делает напарник; миграции, права и публикацию проверять особенно внимательно.

Не коммитить .env, токены, ключи, production dumps, временные чаты и node_modules. Репозиторий остаётся приватным: права участника назначает владелец отдельно. Этот пакет не рассылает приглашения и не меняет доступ.

## Предлагаемые этапы до защиты

| Этап | Результат | Критерий |
|---|---|---|
| 1. Согласование | Стек, сценарии, пилотные данные, право публикации | Открытые решения имеют ответственных |
| 2. Вертикальный сценарий | Подтверждённый материал → опубликованная карточка → поиск → ответ с ссылкой | Источник открывается и соответствует ответу |
| 3. Каталог/CMS | Иерархия, филиалы, языки, импорт, роли, модерация | Черновики/чужие филиалы не раскрываются |
| 4. Контент | Справка, новости, коллекции, выставка, обязательные блоки | Покрытие матрицы требований видно, недоделки перечислены |
| 5. Проверки и защита | KK/RU/EN, мобильный сценарий, ошибки, восстановление, презентация | Нет заявлений о несуществующей готовности |

Это порядок, не обещание выполнить полный ТЗ за четыре дня. Если показывается ограниченное демо, честно указать, какие обязательные функции остаются за его пределами. Работающие права и реальные источники важнее большого числа фиктивных экранов.

## Минимальный демонстрационный маршрут

Вопрос на главной → короткий ответ с источником → карточка материала → просмотр разрешённой копии → возврат в чат; затем ручной поиск по шифру, переключение языка, филиал с маршрутом; в admin — черновик → проверка → публикация → обновление поиска. Отдельно показать «не найдено» и недоступность модели без блокировки каталога.
