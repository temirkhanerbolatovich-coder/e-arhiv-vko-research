# Ограничения, индексы и транзакции

Это требования к будущим PostgreSQL-миграциям и серверной логике. DBML намеренно не выдается за исполняемую миграцию: часть межтабличных инвариантов требует транзакций, составных FK или триггеров. Ниже указан предполагаемый уровень обеспечения.

## Ключи и целостность

| Правило | Реализация |
|---|---|
| Все ссылки ведут к существующим строкам | FK; при удалении по умолчанию RESTRICT |
| Подтип совпадает с resources.kind и существует ровно один подходящий подтип | Транзакция создания + deferred constraint trigger; обязателен негативный тест |
| Фонд/опись/дело уникальны в родителе | UNIQUE(branch_id, number), UNIQUE(fund_id, number), UNIQUE(inventory_id, number) |
| Номера текстовые, без потери суффиксов/нулей | text + явные правила нормализации, исходное значение сохранено |
| Даты неполные/приблизительные | date_label + границы + precision; CHECK from <= to при обеих границах; NULL означает неизвестно |
| Числа листов/размеры/позиции неотрицательны; номер страницы >=1 | CHECK; неизвестное число листов NULL |
| kk/ru/en для интерфейсных редакций | CHECK locale IN (...); язык оригинального документа отдельный и может быть другим |
| Опубликованная версия того же ресурса и языка | Составной FK publications(resource_id, locale, revision_id) → versions(resource_id, locale, id), он есть в DBML |
| Публиковать можно только одобренное | Серверная транзакция + проверка состояния/права; обход прямой записью запрещён роли приложения |
| Цитируемый chunk принадлежит revision | Составной FK (chunk_id, revision_id) в физической миграции; подготовить UNIQUE(id, revision_id) на chunks |
| Наследование филиала по каталогу | Проверка funds.branch_id против resources.owner_branch_id; для потомков вычислять из родителя, не доверять клиенту |
| Исторические имена и связи не образуют циклы | Проверка дерева places/pages/categories/navigation; запрет самовключения коллекций/экспонатов |
| Область роли корректна | CHECK(global AND branch_id IS NULL OR branch AND branch_id IS NOT NULL) |
| Нет повторного глобального назначения роли | Partial UNIQUE(user_id, role_id) WHERE branch_id IS NULL; отдельный UNIQUE для branch |
| Регулярные часы или исключение | XOR weekday/specific_date, weekday 1–7; валидные интервалы и timezone |
| Переход в меню | XOR resource_id/internal_path; внутренний путь разрешён сервером |
| Координаты | CHECK широта -90..90, долгота -180..180; обе известны либо обе NULL |

Типы/статусы в DBML пока `text` с перечислением в примечании. Перед запуском приложения они должны стать CHECK/enum/справочниками. Дефолты UUID, timestamps, последовательностей и безопасных статусов задаются миграциями; в проекте нет скрытого auto-publish.

## Версии и публикация

`resource_versions` — неизменяемый контент: изменение создаёт следующую редакцию. Workflow может меняться с записью moderation_actions. Публикация атомарно переключает указатель, фиксирует аудит и создаёт index_job. Редактор видит состояние конфликта, если кто-то опубликовал более свежую версию.

`public_snapshot` — только разрешённые данные с версионированной схемой по типу ресурса; в нём могут быть переведённые адреса, подписи/alt, архивные реквизиты и упорядоченные связи. Это не место для паролей, закрытого OCR, сырых импортов или произвольного HTML. Публичная выдача использует снимок и пересекает его с текущими правами связанных ресурсов/файлов. Изменения структурных полей и состава коллекции требуют новой публикации.

## Индексы

- B-tree на FK и частые сочетания: branch/number, parent/number, период/тип, опубликованные даты, язык/маршрут.
- GIN на подготовленное поисковое представление разрешённого текста; параметры RU/EN/KK тестируются отдельно. Наличие PostgreSQL само по себе не обеспечивает качественную морфологию KK.
- Индекс на files.sha256 для кандидатов в дубли. Контентное совпадение не даёт права раскрывать файл в другом контексте.
- Векторный индекс выбирается после модели, размерности и измерения корпуса. Нельзя смешивать в одном поиске embeddings разных моделей; запрос использует ту же модель, что и индекс.
- Partial индекс ожидающих index_jobs; индексы expires_at для очистки сессий и временных данных.
- Индексы audit_logs по actor/time и resource/time. Сырые payload и весь body без нужды не индексируются.

Это список кандидатов; окончательный набор проверяется EXPLAIN ANALYZE и нагрузкой, а не создаётся без измерений.

## Удаление и хранение

Опубликованные материалы сначала снимаются с публикации; поиск и кэши инвалидируются. Родитель каталога с потомками не удаляется автоматически. Сотрудник деактивируется, история авторства сохраняется. Ошибочные черновики допускается удалить после проверки связей с аудитом.

Истечение chat_session удаляет сообщения, цитаты и оценки в контролируемой транзакции/задаче очистки. Производный chunk можно перестроить, но цитата хранит revision, hash и locator; ссылку chunk_id при очистке обнуляют явно. Сроки хранения задаются конфигурацией после согласования, не бессрочными дефолтами.

Кэши и ответы чата при отзыве доступа: инвалидировать связанные ответы/не выдавать сохранённый текст, если его источники больше недоступны. Уже показанный пользователю текст технически невозможно «забрать обратно»; закрытые данные не должны попадать в него изначально.

## Резервное копирование

Резервировать PostgreSQL, файлы и соответствие storage_key/версий согласованно. Проверять восстановление в отдельной среде, включая просмотр файлов и ссылки. RPO/RTO, частота и срок хранения копий — открытые эксплуатационные решения; наличие файла backup не доказывает восстановимость.
