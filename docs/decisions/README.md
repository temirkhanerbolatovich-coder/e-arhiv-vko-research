# Решения и открытые вопросы

Дата всех записей: 09.11.2026. Статус архитектурных решений — **Proposed**, если явно не указано иное. Предложения не считаются утверждёнными заказчиком.

## ADR-001: PostgreSQL и производный смысловой индекс

**Контекст:** связанный архивный каталог, версии, права, поиск и чат. **Варианты:** PostgreSQL + pgvector; PostgreSQL + отдельная поисковая система; отдельная векторная БД. **Решение:** начать с PostgreSQL и pgvector, файлы хранить отдельно. **Причина:** единые транзакции/связи и меньше эксплуатационных компонентов для двух разработчиков. **Последствия:** качество KK-поиска, модель embeddings, индекс и производительность требуют измерений. **Риски:** рост корпуса и задержек. **Далее:** расширять поиск только по результатам тестов. [PostgreSQL FTS](https://www.postgresql.org/docs/current/textsearch.html), [pgvector](https://github.com/pgvector/pgvector).

## ADR-002: Общая идентичность и публикуемые версии

**Контекст:** новости, филиалы, фонды и выставки должны иметь языки, маршруты, проверку и источники. **Варианты:** повторять эти поля в каждом модуле; универсальная JSON-таблица всего; небольшой resources + предметные таблицы. **Решение:** третий вариант, редакции и опубликованный snapshot. **Причина:** общие правила при сохранении типизированной иерархии. **Последствия:** нужен контроль kind/подтипа и снимков. **Риски:** чтение черновых таблиц публичным API; предотвращается единым сервисом публикации. **Далее:** физические миграции и негативные тесты.

## ADR-003: RAG по разрешённым источникам

**Контекст:** чат должен выдавать факты и реальные переходы. **Варианты:** свободный чат модели; готовые FAQ; извлечение материалов + генерация. **Решение:** последнее, с точным поиском и FAQ как источниками. **Причина:** проверяемость и покрытие сайта. **Последствия:** индекс, версии, цитаты и проверка доступа обязательны. **Риски:** галлюцинации, устаревшие chunks, prompt injection. **Далее:** проверенный набор запросов, фильтрация источников до передачи модели, оценка фактов человеком.

## ADR-004: Импорт через staging и provenance

**Контекст:** строки CSV не равны архивным сущностям, есть ошибки OCR и отсутствующие файлы. **Варианты:** прямой импорт; ручной ввод; staging с проверкой. **Решение:** staging + источники + идемпотентное сопоставление. **Причина:** сохраняет оригинал и объясняет ошибки. **Последствия:** требуется работа архивиста. **Риски:** неверное объединение одноимённых фондов/дублей. **Далее:** образцы реальных описей и дел, согласование правил.

## ADR-005: Чат первым, все обязательные разделы доступны

**Статус:** акцент на чате выбран пользователем; компоновка главной предложена, заказчиком не утверждена. **Контекст:** простота входа и обязательные блоки 5.1. **Варианты:** традиционная главная; только чат; чат первым плюс обязательные блоки. **Решение:** предложить третий вариант. **Последствия:** обычная навигация сохраняется, ИИ не единственная точка доступа. **Риски:** перегрузка главной при реализации. **Далее:** отдельное согласование дизайна. Макеты здесь не публикуются по указанию пользователя.

## Что решить до реализации

| Вопрос | Кому подтвердить | Что зависит |
|---|---|---|
| Современные филиалы и реквизиты | Архив | Импорт и права филиалов |
| Реальные форматы фонд/опись/дело/документ | Архив + backend | Ключи, обязательность полей, корректная миграция |
| Права на карточки, файлы, OCR | Архив | Публичный каталог и контекст ИИ |
| Модель, провайдер, регион обработки, бюджет | Команда + заказчик | Embeddings, размерность, конфиденциальность, задержка |
| Политика публикации/согласования переводов | Архив | Роли, модерация, полнота KK/RU/EN |
| Хостинг, storage, backup RPO/RTO | Команда + заказчик | Развёртывание и восстановление |
| Сроки хранения чата/обратной связи | Заказчик | Очистка, аналитика, настройки |
| Frontend/backend стек | Два разработчика | Auth, миграции, локальный запуск |
| Демонстрационный объём и дизайн | Команда + заказчик | Подготовка защиты 13 ноября |
