# Локальная подготовка материалов сотрудником

Обновлено 12 ноября 2026 года. Интерактивные сценарии подготовлены в ветке `redesign-government`; 12 ноября пользователь разрешил их публикацию вместе с редизайном. Их данные по-прежнему локальны для вкладки. Серверные операции и ИИ не изменены.

## Что доступно

| Маршрут | Сценарий |
|---|---|
| `#/admin/catalogue` | Поиск опубликованной записи → «Подготовить изменения» |
| `#/admin/catalogue?record={id}` | Изменение описания и реквизитов, проверка диапазона лет, сравнение с оригиналом, локальный черновик и экспорт JSON |
| `#/admin/files` | Выбор нескольких файлов, проверка расширения/MIME/сигнатуры/размера, связь с черновиком, подпись и источник, просмотр и удаление из очереди |
| `#/admin/content` | Пустой список локальных материалов, поиск и фильтр по типу, создание страницы/новости/выставки/коллекции |
| `#/admin/content?material={localId}` | Заголовок, текст, источник, категория и RU/KK/EN, предпросмотр, проверка готовности оригинала и экспорт |
| `#/admin/translations?material={localId}` | Оригинал и перевод рядом, переключение KK/EN/RU, локальное сохранение и отметка проверки |

Файлы реализации: `admin-workbench.js`, `admin-workbench-i18n.js`, `admin-workbench.css`. Они подключаются в `index.html`; существующая оболочка `admin-live.js` передаёт язык и текущего сотрудника. Вход, чтение опубликованных данных и существующие операции панели продолжают использовать прежний API.

## Состояние и границы

- Данные хранятся **только в памяти текущей вкладки**. Переходы между разделами и переключение темы, масштаба и языка сохраняют ввод. Перезагрузка, выход и обнаруженное завершение сессии очищают подготовленные материалы. При перезагрузке с введёнными данными браузер может запросить подтверждение ухода.
- Кнопка локального сохранения фиксирует состояние черновика внутри вкладки. Она не вызывает API и не заменяет выгрузку файла, если черновик нужен после закрытия страницы.
- Новые разделы не выполняют загрузку файлов, изменение записей или публикацию на сервере. Публичная карточка остаётся прежней. Статус «Готов к передаче» означает заполнение оригинала и подписей связанных файлов; он не означает публикацию или готовность всех переводов.
- При смене сотрудника локальные данные очищаются. В интерфейсе действуют текущие права: каталог — `catalog.edit`; публикации и переводы — `content.create` или `content.publish`; файлы — любое из этих трёх прав. Для администратора филиала проверяется принадлежность открываемой записи. Это ограничения интерфейса; будущие операции записи обязан независимо защищать сервер.
- Отметка проверки перевода доступна сотруднику с `content.publish` или `moderation.review`, если сам раздел доступен его роли. Изменение перевода снимает отметку этого языка, изменение оригинала — отметки всех переводов.
- Текст материалов отображается как текст, без выполнения HTML. Ссылки, форматирование и автоматический перевод редактор не генерирует.

## Файлы

Поддержана локальная очередь PDF, JPEG, PNG и TIFF: до 20 МБ на файл, до 50 МБ и 20 файлов на вкладку. Пустые файлы, несовпадение формата и повторная добавка того же файла отклоняются. Один ошибочный файл не удаляет остальные выбранные сканы.

PNG/JPEG отображаются в диалоге; для PDF предусмотрено открытие в отдельной вкладке, для TIFF — скачивание оригинала. Ошибка декодирования изображения показывается отдельно. Временные URL просмотра освобождаются при закрытии диалога или уходе с экрана. Исходный файл на компьютере не меняется и не удаляется.

Проверка заголовка файла не подтверждает целостность всего документа и отсутствие вредоносного содержимого. Серверная проверка, карантин, постоянное хранение, превью TIFF, аудио и видео относятся к отдельному этапу.

## Передача бэкенд-разработчику

Выгрузки JSON — **формат локального черновика v1**, а не существующий контракт записи API и не файл резервной копии БД.

- Общие поля: `format`, `version`, `localOnly`, `type`, `exportedAt`, `payload`, `files`.
- Черновик записи: `resourceId`, `baseUpdatedAt`, `branchId`, `values`. Годы экспортируются как число или `null`. `baseUpdatedAt` позволит будущему обработчику обнаруживать конфликт с более новой версией записи.
- Черновик публикации: `localId`, `kind`, `originalLocale`, `source`, `category`, `versions` и `readyForHandoff`. Каждая языковая версия содержит `title`, `text`, `reviewed`.
- Реестр файлов: имя, размер, формат, `lastModified`, локальная связь `record:{id}` или `content:{localId}`, подпись и источник. **Байтов файлов в JSON нет**; оригиналы передаются отдельно.

Перед интеграцией нужно согласовать защищённое чтение и изменение записи, версии/конфликты, загрузку и проверку файлов, сохранение языковых версий и отдельную процедуру модерации. Подключение заменяет локальные обработчики после ответа сервера; не следует менять подпись кнопки на «Сохранено» до подтверждения операции. Не использовать публичное чтение карточки как разрешение на запись.

## Проверки

Запустите сайт по основной инструкции. Используется локальный адрес `http://127.0.0.1:4173/` и существующие демо-учётки. Тесты входят только в локальный комплект до согласования публикации.

Браузерные проверки используют Puppeteer из существующего инструментария диаграмм, без новых зависимостей приложения:

```powershell
npm ci --prefix tools/docs
node frontend/tests/admin-workbench.browser.cjs
node frontend/tests/admin-workbench-roles.browser.cjs
```

Если инструментарий уже установлен отдельно, задайте `ARCHIVE_BROWSER_TOOLS` абсолютным путём к его папке с `node_modules`. Скриншоты и тестовые выгрузки создаются во временной папке, путь выводится при запуске.

Проверены: сохранение ввода, сравнение изменений, диапазон лет, экранирование текста, JSON-выгрузки, неверный формат и размер файла, ошибка просмотра, отмена/подтверждение удаления, сброс отметки перевода, исходные данные после редактирования, отсутствие запросов записи из новых сценариев, очистка после выхода, анонимный доступ и четыре роли, область филиала, ошибка чтения с повтором. На новых экранах проверено отсутствие горизонтального переполнения при 1440/RU/100%, 390/EN/100% в тёмной теме и 320/KK/200%.

Ручная работа со скринридером и проверка на физических устройствах не выполнялись. Серверное хранение, публикация, антивирус, все форматы документов и полный аудит доступности этими проверками не подтверждаются.
