# Гостевая книга: локальный фронтенд

Состояние от 12 ноября 2026 года. Публикация фронтенда разрешена пользователем. Изменена только клиентская часть. Существующая отправка `{kind, message}` в `POST /api/v1/feedback` сохранена. Публичный API ленты и ответы сотрудников на сервере не реализованы этим этапом.

## Просмотр

- `#/section/feedback` — форма и состояние «Публичная лента пока недоступна». Это не утверждение об отсутствии сообщений в архиве.
- `#/section/feedback?preview=messages` — отдельно обозначенный образец ленты с семью условными сообщениями и примерами ответов. Они не происходят из гостевой книги заказчика, не отправляются в БД и не являются отзывами посетителей.
- `feed-type=review|suggestion|wish|error`, `feed-page=N` — фильтр и страница образца. При смене категории страница сбрасывается. Состояние сохраняется в ссылке и при смене языка.

Кнопки «Оставить сообщение» и «Как публикуются сообщения» переводят фокус к форме и правилам без подмены хеш-маршрута. Фильтры и пагинация ленты не перерисовывают форму и не очищают введённый текст. Правила и элементы ленты доступны на RU/KK/EN; содержание реальных сообщений не переводится автоматически.

В форму не добавлены неподдерживаемые поля имени, почты или филиала: текущий сервер их не принимает и не сохраняет. До отдельного согласования полей и обработки данных такие сведения не собираются интерфейсом.

## Компонент ленты

`guestbook-feed.js` экспортирует `renderGuestbookFeed(container, language, configuration)`. Это интерфейс компонента, **не контракт существующего сетевого API**.

Конфигурация:

- `state`: `unavailable` по умолчанию; также `loading`, `error`, `ready`.
- `items`: массив публичных проекций сообщений, только для `ready`.
- `retry`: необязательный обработчик повтора в состоянии `error`.
- `preview: true`: явный режим условных примеров, включаемый страницей по параметру `preview=messages`.

Поля публичного сообщения:

```json
{
  "status": "published",
  "kind": "suggestion",
  "publicName": "Согласованное имя для публикации",
  "message": "Текст, разрешённый к публикации",
  "publishedAt": "2026-11-12T08:00:00Z",
  "publicReply": {
    "status": "published",
    "message": "Текст публичного ответа"
  }
}
```

Это иллюстрация структуры, а не реальное сообщение. Компонент исключает строки без `status: published`, неизвестные категории и пустые сообщения. Ответ показывается только при отдельном `publicReply.status: published`. Почта, служебное примечание, причина отклонения и прочие приватные поля не выводятся. Содержимое экранируется и отображается как текст. Дата показывается только при корректном значении.

Эти проверки не заменяют серверное разграничение доступа. Нельзя передавать в публичный компонент административную очередь целиком. Сервер должен возвращать только разрешённую публичную проекцию; одобрение модератором не следует автоматически считать согласием на публичное размещение личных данных.

Сейчас пагинация выполняется по переданному массиву, по три сообщения на страницу. Для рабочей ленты нужно согласовать серверные фильтры, страницы, сортировку, количество записей и правила опубликованных ответов. Обработчик чтения должен учитывать уход со страницы, отменять или игнорировать устаревшие ответы и сохранять форму отдельно от загрузки ленты.

## Что осталось подключить отдельно

Постоянное хранение, публичное чтение, публикация/снятие сообщений, редактор ответов, подтверждённые правила обработки данных, дополнительные поля формы и защита повторной отправки при неопределённом сетевом результате. Изменения сервера и ИИ не входят в этот этап.

## Проверки

Используется существующий инструментарий Puppeteer из `tools/docs`; установка и альтернативный путь `ARCHIVE_BROWSER_TOOLS` описаны в [локальных сценариях сотрудника](LOCAL_STAFF_WORKFLOWS.md#проверки).

```powershell
node frontend/tests/guestbook-branches.browser.cjs
```

Проверены состояние недоступной ленты, фильтры и страницы образца, сохранение текста формы, фокус и маршруты, исключение сообщений до публикации и приватных полей, экранирование HTML и повтор после ошибки. Также проверены RU/KK/EN, светлая/тёмная темы, 1440/390/320 px, текст 200% на 320 px и карточки филиалов. Повторно пройдена существующая локальная проверка отправки формы с задержанным ответом, сменой языка и ошибками сервера.

Тесты новых сценариев используют условные данные в браузере и не публикуют отзывы на сайте. Скринридер, физические устройства и работа публичного серверного API не проверялись этим этапом.
