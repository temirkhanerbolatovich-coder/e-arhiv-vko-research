# Подключение фронтенда архива ВКО к бэкенду

## Быстрый ориентир

Для проверки интеграции запускайте сайт и API вместе: [инструкция](README.md). Фактические маршруты и проверки прав определяются [backend/src/http/app.ts](../backend/src/http/app.ts), настройки публикации — [Vercel](../docs/deployment/vercel.md).

Демо на Vercel использует снимок в памяти. Наличие формы или демонстрационного состояния не подтверждает постоянное хранение и полноту серверного сценария. Следующий блок фиксирует интеграцию от 11 ноября, а таблица после него сохраняет исходный план передачи фронтенда.

> **Статус на 11.11.2026:** бэкенд реализован в [`backend/`](../backend/README.md). Подключены главная и чат (`POST /api/v1/chat/messages`, оценка ответа), каталог (`GET /catalog`), новая карточка материала `#/resource/{id}` (`resource.js`), филиалы с координатами (`GET /branches`), отзывы (`POST /feedback`) и экраны сотрудника: вход, модерация, новая запись с ИИ-распознаванием, импорт/экспорт, аналитика, отзывы, журнал, роли и сотрудники (`admin-live.js`). Общий клиент — `api-client.js`. Если API недоступен, модули работают на локальных примерах, как раньше. Ниже — исходный план интеграции; фактические контракты см. в `backend/src/http/app.ts`.

Фронтенд в `frontend/` открывается как статический сайт. [README](README.md) описывает экраны и запуск. Модули уже отображают каталог, документы, чат, справочные разделы и 18 экранов админпанели на русском, казахском и английском. Списки, ответы чата и административные состояния работают на локальных примерах. Прототип не вызывает серверный API, а действия изменения данных в админпанели отключены.

Сайт информационный. Разделы государственных и платных услуг публикуют сведения и направляют на официальные внешние ресурсы. Публичная форма принимает только отзывы, предложения и пожелания о сайте после подключения API. Заявления, архивные запросы, заказы, оплата и отслеживание обращений в этот интерфейс не входят. [ТЗ и уточнения](../docs/requirements/README.md).

## Что подключать в коде

| Экран и текущий маршрут | Точка подключения | Данные и состояния |
|---|---|---|
| Главная `#/`, `#/ask`, диалог `#/chat` | `app.js` передаёт в `chat.js` сообщения, обработчики и функцию `answerFor`. Заменить выдачу подготовленного ответа в `ask`/`answerFor` на запрос к серверу. | Текст вопроса, язык, идентификатор диалога, ответ и карточки источников. Использовать существующие состояния ожидания, отсутствия результата, ошибки и ограничения доступа. Параметр `question` подставляет текст в поле, отправка остаётся отдельным действием. |
| Каталог `#/catalog` | `catalog.js`, `renderCatalog` и `updateResults`. Оставить поля фильтров, адрес страницы и компоненты отображения. Заменить локальный поиск по двум записям серверной выдачей. | `q`, `type`, `period`, `fund`, `inventory`, `case`, `year-from`, `year-to`, `author`, `topic`, `place`, `branch`, `sort`, `size`, `page`. Сочетать фильтры. Сохранять выбранное при смене языка. Страницу сбрасывать при изменении фильтров. |
| Фонд, опись, дело, документ | `fund.js` и `ridder-record.js`. Маршруты `#/fund/r1`, `#/ridder/fund/261`, `#/ridder/inventory/1`, `#/ridder/case/248`, `#/ridder/document/1` показывают отдельные образцы. Для новых карточек добавить маршрут со стабильным идентификатором ресурса. | Проверенная иерархия, архивный шифр, название и язык оригинала, датировка, место хранения, источник и статус копии. Номера из демонстрационных URL не являются глобальными идентификаторами. |
| Просмотр копии `#/document?file=pricelist-ru&page=1` | `document-viewer.js`, сейчас белый список двух PDF прейскуранта и по 15 изображений страниц на язык. | Получать разрешённые варианты просмотра и скачивания. Сохранить перелистывание, масштаб и состояние ошибки загрузки. Выдавать только доступные страницы. |
| Филиалы `#/section/branches` | `branches.js`, `branch-map.css`. Справочник локальный. Карта головного архива включается посетителем. | Публичные названия, адрес, контакты, график. Координаты и `show_on_map` передавать только после подтверждения. Пустые поля оставлять пустыми. |
| Публикации и справка `#/section/...`, `#/exhibition`, `#/memory`, `#/calendar`, `#/places`, `#/person` | `sections.js`, `news.js`, `exhibition.js`, `memory.js`, `calendar.js`, `places.js`, `person.js` и профильные модули разделов. | Подключать проверенные опубликованные версии. Новости сохраняют фильтры и пагинацию в URL. Исторические тексты могут сохранять исходный язык. Вести ссылку на первоисточник и дату, где они известны. |
| Обратная связь `#/section/feedback` | В `feedback.js` обработчик `submit` сейчас меняет только надпись, а черновик хранится в памяти страницы. | Подключить отправку после согласования категорий и сроков хранения. Показать успешную отправку только после ответа API. При ошибке оставить черновик. UI сейчас предлагает `suggestion`, `review`, `error`, а проект БД предусматривает `review`, `suggestion`, `wish`. Согласовать отображение `error` и `wish` до подключения. |
| Экраны сотрудника `#/admin/*` | `admin.js`, `admin-catalog.js`, `admin-content.js`, `admin-management.js`. Полный список экранов в [README](README.md#что-свёрстано). | Вход и сессия, роли и филиалы, каталог и файлы, импорт, контент и переводы, модерация, отзывы и журнал. Включать формы по мере готовности защищённых операций. |

`app.js` читает хеш в браузере. Например, при открытии `http://localhost:4173/#/catalog?fund=261` сервер отдаёт `index.html` и не получает параметры после `#`. Фронтенд должен сам передать их в API. На первом этапе можно сохранить текущие адреса. Удобная конфигурация для совместного запуска — один origin со статическими файлами и относительными запросами `/api/v1/...`, например через локальный прокси. Для разных origin использовать явный список разрешённых origin. При подключении API открывать сайт через HTTP/HTTPS, а `file://` использовать только для локального просмотра прототипа.

## Предлагаемые API и форматы

Маршруты и поля ниже — рабочий пример для обсуждения. Реальные контракты, типы, параметры и коды ошибок зафиксируйте с фронтенд-разработчиком до замены локальных данных. Ключи модели, БД и файлового хранилища задаются на сервере вне Git.

| Область | Примеры маршрутов | Что получает интерфейс |
|---|---|---|
| Каталог | `GET /api/v1/catalog?locale=kk&fund=261&year-from=1941&page=1&size=10`, `GET /api/v1/resources/{id}?locale=kk` | `items`, `page`, `size`, `total`. В карточке — опубликованное представление, цепочка родителей, источник и статус копии. Фильтры и допустимые сортировки валидируются на сервере. |
| Копии | `GET /api/v1/resources/{id}/files`, `GET /api/v1/files/{id}/pages/{number}`, `GET /api/v1/files/{id}/download` | Доступные превью и разрешение скачивания. Закрытый файл не выдаётся по прямому ID. |
| Публикации | `GET /api/v1/sections/{slug}?locale=kk`, `GET /api/v1/branches?locale=kk` | Опубликованная страница, записи раздела или филиалы с контактами и графиком. |
| Чат | `POST /api/v1/chat/messages`, `PUT /api/v1/chat/messages/{id}/rating` | Отправка `{question, locale}` в сессии посетителя. Ответ содержит статус и источники. Оценка `-1` или `1` доступна владельцу сессии. |
| Отзывы | `POST /api/v1/feedback` | Приём сообщения о сайте на модерацию. Успешный ответ без номера официального обращения. |
| Администрирование | `GET /api/v1/admin/session`, запросы под `/api/v1/admin/` по каталогу, контенту, файлам, отзывам и настройкам | Сессия, действия в рамках роли и филиала, безопасные ошибки и журналирование. Импорт/файлы могут возвращать идентификатор задания и статус обработки. |

Пример записи каталога. Значения условные, `null` обозначает неизвестное поле.

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "kind": "document",
  "title": "Условное название документа",
  "locale": "ru",
  "originalLanguage": null,
  "reference": "Ф. 261, оп. 1, д. 248, л. 1",
  "period": { "fromYear": 1941, "toYear": 1941 },
  "branchId": null,
  "copyStatus": "unknown"
}
```

Пример ответа чата без найденного источника.

```json
{
  "messageId": "22222222-2222-4222-8222-222222222222",
  "status": "no_results",
  "answer": "Подходящий открытый источник не найден. Уточните фонд, год или населённый пункт.",
  "sources": []
}
```

Для `answered` каждый источник содержит `resourceId`, идентификатор редакции, проверенный заголовок и ссылку, которую построил сервер. Шифр и позиция на странице добавляются только при наличии. Полезно различать `no_results`, недоступность сервиса и ограниченный доступ. Статус ограничения можно показывать, когда сама запись допускается к публичному описанию. Не подтверждайте существование закрытого материала, если его метаданные внутренние. Текст ответов, названия и подписи из API вставлять через `textContent` или экранировать перед сборкой разметки. Ссылки проверять по разрешённым маршрутам и протоколам. Перед повторным поиском отменять предыдущий запрос или отбрасывать устаревший ответ, чтобы смена фильтра или языка не перезаписалась результатом старого запроса.

## Порядок подключения

1. **Данные и публичные чтения.** Согласовать минимальные физические миграции по [проекту БД](../docs/database/README.md) и [ограничениям](../docs/database/constraints.md). Связать фонд, опись, дело и документ по подтверждённым идентификаторам. Использовать [описание импорта](../docs/data/inventory-and-migration.md) и сохранять происхождение строк. Перенести согласованные данные через staging. Импорт, проверка и публикация — отдельные операции.
2. **Каталог, карточки и файлы.** Извлекать публичные поля из `resource_publications` и проверенной редакции `resource_versions.public_snapshot`. Отдельно проверять актуальную видимость метаданных и доступ к конкретному файлу (`resources`, `resource_files`, `files`, `document_pages`). Разрешение просмотра и разрешение скачивания проверяются отдельно. Мастер-копии и закрытые файлы держать вне папки со статическими публичными ресурсами. При отзыве доступа блокировать прямые ссылки и превью на сервере, обновить производные данные и кэш.
3. **Контент и языки.** Для интерфейса сохранять `ru`, `kk`, `en`. Для данных возвращать фактический язык опубликованной редакции и язык оригинала, когда он известен. Если проверенного перевода нет, можно показывать разрешённый оригинал с пометкой. Черновик перевода не должен попадать в публичную выдачу. Согласовать канонические маршруты и переходы со старых ссылок.
4. **Админпанель и отзывы.** Подключить серверную авторизацию и проверку роли и филиала на каждый запрос. Проверять сессию, отклонять запросы без полномочий, защищать операции записи. Добавить проверку файлов и их карантин, отчёты импорта, версии контента и аудит. Публикацию одобренной редакции, запись аудита и создание задания индексации выполнять согласованно. Условные демонстрационные записи не импортировать в рабочую БД.
5. **Поиск и чат.** Сначала обеспечить точный поиск по шифру и тексту. Затем подключить модель с подбором разрешённых источников. Перед передачей контекста и выдачей ссылки заново проверять актуальную публикацию и права. Модель получает минимальные разрешённые фрагменты и не управляет БД. При сбое модели дать перейти в каталог и показать проверяемые результаты обычного поиска, если они доступны. [Архитектура](../docs/architecture/overview.md) · [Модель защиты](../docs/security/security-model.md).

## Проверка совместной сборки

- Каталог возвращает пустую выдачу и корректную страницу результатов. Прямая ссылка с фильтрами открывается после перезагрузки, смена языка сохраняет параметры. Цепочка фонд → опись → дело → документ ведёт к тому же материалу.
- Черновик и закрытая карточка недоступны анонимно. Для карточки с открытыми метаданными и закрытой копией работают описание и шифр, а запросы страниц и файла отклоняются. Отзыв доступа проверяется отдельно для ссылки из чата и превью.
- Чат показывает ожидание, результат с рабочими ссылками, пустой результат и ошибку. Сбой или повтор не дублируют отправку и не возвращают устаревший ответ. Нет фактического ответа без подтверждённого открытого источника.
- В админпанели анонимный запрос не проходит, сотрудник не может менять записи другого филиала. После согласования меняется только одобренная языковая редакция. Повторный импорт не создаёт дубли.
- Отзыв проходит валидацию и сохраняется для модерации. Черновики, служебные контакты и личные данные не попадают в публичный список и ИИ-индекс.
- Пройти ключевые сценарии на RU/KK/EN, с клавиатурой и при увеличении текста. Проверить приёмку вместе с архивом после согласования контента, переводов, прав на материалы и обработки данных. [План проверок](../docs/testing/README.md).
